# Lab Seminars

랩 내부 세미나(= 리딩 그룹) 기록입니다. **매주 수요일 15:00**, 60분, 대면 원칙.

운영 규칙은 핸드북에 있습니다 → [연구실 운영 규칙 §1](/handbook#policy-operations)
사이트에서는 [Seminars](/lab-seminars) 페이지로 보입니다.

> 초청 강연·외부 워크숍은 여기가 아니라 `content/seminars/` 입니다.
> 이 폴더는 **우리끼리 하는 논문 발표**만 담습니다.

## 폴더 구조

```
content/lab-seminars/
├── README.md                    이 파일
├── _template.md                 세미나 노트 템플릿
├── _rotation-2026-fall.yaml     학기별 발표 순서
└── 2026-fall/                   학기 폴더 (첫 노트를 만들면 생깁니다)
    ├── 2026-09-03.md
    └── 2026-09-10.md
```

- 학기 폴더는 `YYYY-fall` / `YYYY-spring`.
- 노트 파일명은 **`YYYY-MM-DD.md`** — 세미나를 한 날짜입니다.
- `_` 로 시작하는 파일은 콘텐츠가 아닙니다 (로더가 건너뜁니다).
  로테이션 YAML과 템플릿이 세미나 노트로 잘못 읽히지 않는 이유입니다.

## 발표 순서 (로테이션)

`_rotation-YYYY-학기.yaml` 하나에 그 학기 배정이 들어갑니다.

- **학기 초에 학생끼리 협의해서 채웁니다.** PI가 지정하지 않습니다.
- 개인 사정이 생기면 서로 교환하세요. Slack에서 합의한 뒤 이 파일을 고치면 됩니다.
- 공개 파일입니다 — 누구나 보고 고칠 수 있습니다.

## 노트 쓰기

**발표한 사람이** 세미나 당일에 씁니다. 나중에
"그 논문 우리가 언제 읽었더라"를 검색할 수 있게 하는 것이 목적입니다.

```bash
cp content/lab-seminars/_template.md content/lab-seminars/2026-fall/2026-09-03.md
```

길게 쓸 필요 없습니다. **논문 정보 + 세 줄 요약 + 토론에서 나온 것**이면 충분합니다.
빈 채로 두느니 짧게라도 남기는 편이 낫습니다.

발표 전에 미리 만들어 두어도 됩니다 (`status: upcoming`).
그러면 사이트에 "다음 세미나"로 보이고, 참석자가 논문 링크를 미리 확인할 수 있습니다.
